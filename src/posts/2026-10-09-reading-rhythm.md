## 屏幕上的阅读，首先是一种体力活

我们很少把“读一篇文章”当成体力活。但眼睛要在行与行之间来回移动，脖子要保持一个姿势，注意力要抵抗随时可能弹出的通知。排版能做的，是让这些动作尽量省力。

所以我看一个阅读页面时，最先注意的不是字体多漂亮，而是：一行是不是太长，行与行是不是太挤，段落之间有没有喘息的地方。

## 行高不是一个数字

行高常被当成一个随手填的值：1.5、1.6、1.8。它当然是一个数字，但背后是行与行之间的空气。字号越大，需要的绝对行距通常越大；中文没有英文那样明显的升部与降部，行距不够时，字会挤成一片灰色的墙。

这个博客的正文用了 17px 字号和 1.8 的行高，阅读列宽约 43rem。不是在追求某个“最佳参数”，而是让一行落在 35 到 45 个汉字之间，眼睛回行时不用太费力。

```css
:root {
  --reading-width: 43rem;
  --body-size: 17px;
  --body-leading: 1.8;
}

.prose {
  max-width: var(--reading-width);
  font-size: var(--body-size);
  line-height: var(--body-leading);
}
```

真正重要的是关系，而不是数字本身：字号、行高、宽度要一起调。把正文缩到 15px 却保留 43rem 的宽度，一行会塞进太多字；把宽度收到 30rem 却用 2.0 的行高，页面又会显得松散。

## 留白不是空白

留白经常被误解成“什么都没放”。但在阅读页面里，留白是结构的一部分：标题上方的距离说明新章节开始了，段落之间的距离说明一个意思结束了，代码块周围的空白说明“这里先停一下”。

我倾向于让留白有层次，而不是到处都一样：

| 位置 | 处理 | 目的 |
| --- | --- | --- |
| 段落之间 | 约 1.2em | 区分意思，但不打断 |
| 标题上方 | 明显大于下方 | 让标题属于下一节 |
| 代码块周围 | 上下各留足空间 | 把代码从正文里托出来 |
| 页面两侧 | 随屏幕收缩 | 手机上不浪费一行宽度 |

留白也不等于把内容摊得很开。移动端上，左右各 20px 左右的内边距通常就够了；再大，正文会变成一根细长的柱子，读起来反而累。

## 对比度与克制

深色模式不是把白色背景换成纯黑、把黑字换成纯白。纯黑背景上的纯白文字会产生明显的光晕，长时间阅读并不舒服。更稳妥的做法是让背景保留一点色相，让正文保持略微柔和的亮度。

这个站点用了偏暖的纸白和偏冷的近黑，强调色是低饱和的墨绿。链接、标签、按钮都用同一种强调色，靠字重、下划线和位置区分层级，而不是堆叠更多颜色。

克制还体现在动效上：卡片悬停时只上移几个像素，导航展开用两百毫秒，主题切换不做过场动画。动效应该帮助人理解“发生了什么”，而不是提醒人“这里有动效”。

## 一点结论

好的阅读排版往往让人注意不到排版。你只会觉得这篇文章读起来顺，愿意往下翻，眼睛不酸，最后记住了内容，而不是记住了字体。

如果只能改一个地方，我会先调行高和正文宽度。它们不显眼，却决定了阅读的节奏。
